# 主控台与 Senera QQ 的资源链路

主控台和 Senera QQ 共用工作区的 HTTP 资源接口。OneBot 负责消息和事件，不承担文件字节传输；消息中的多媒体段引用上传接口返回的 `senera://resource/<id>`，保留文件名、媒体类型和大小。

## 选择、上传与发送

- `Frontend/src/api/resourceUpload.ts` 是 multipart 传输边界，共享 Cookie、CSRF、进度、取消和响应校验。超时按无进度时间计算，前后台切换会暂停和恢复计时。
- `AttachmentUploadTask` 保存同一附件的上传任务和成功资源。并发调用复用进行中的请求，上传失败允许重试，消息发送失败后复用成功资源。任务绑定一个工作区上传端点。
- `ComposerAttachmentDraft` 是两端共用的附件状态控制器：稳定附件 ID、即时上传、进度、取消、重试、持久化、恢复、预览所有权和发送确认后清理均在此实现。React Hook 与 Vue composable 只负责订阅状态和连接界面事件。
- 两端的文件选择事件通过 `enqueueComposerFileSelection` 捕获文件及草稿所有者。控制器先完成文件持久化，再获取当前会话的请求头并发起 HTTP；保存失败保留文件和明确错误，取消后不再发起请求。恢复正文、更新会话资料或重新同步历史不会清空未发送附件。
- `MessageDraftRepository` 使用 IndexedDB 保存附件及资源引用，不存储临时 Blob URL。主控台按服务、工作区及会话分隔；QQ 还区分用户身份、私聊或群聊。
- 文档重建时，仍处于上传中且保存了本地文件的附件自动重新上传；已完成附件复用资源引用，真实请求失败保留原始错误并由用户重试。恢复上传不等于自动重发消息。
- 主控台和 QQ 选择附件后立即启动同一个 HTTP 上传任务；QQ 输入框保留本地预览，发送时复用进行中的请求或成功资源。图片不再为可读性检查额外完整解码一份原图。两端都等待服务端接收确认后清理草稿：主控台以 `run.started` 或 `session.message.queued` 确认，QQ 校验 OneBot 成功响应及消息 ID。
- 断线、超时或协议拒绝保留草稿。QQ 在发送前用共享 `DurableMessageOutbox` 持久化用户明确提交的发送快照和 UUID；恢复同一对话时用相同 UUID 重试。普通未提交草稿不会自动发送。确认先落盘，再清理实际发送的正文、引用和附件，新编辑内容保留。
- OneBot 标准发送动作带可选 `senera_client_message_id` 参数。服务端按 UUID 和规范化内容摘要去重，发送记录与消息在同一 SQLite 事务提交。重复请求返回原消息 ID，复用 UUID 修改正文或收件人会明确拒绝。清空／删除消息后保留精简的确认记录，旧重试不会重建消息。它保证虚拟消息接收去重，不承诺 Agent 执行恰好一次；消息接收确认与模型任务完成是两个阶段。
- 纯附件消息允许空文本；附件以结构化字段传递，不补造“图片”文本作为执行目标。
- QQ 不再使用正文占位符或缓存数组编号决定附件是否发送。正文、引用／@／表情等消息段、附件分别维护；OneBot 边界直接生成消息段数组。修改、清空或替换正文不会删除附件。上传中或失败的附件阻止发送，并提供明确重试；成功响应只清理实际发送快照，新加入的附件继续保留。
- 旧草稿只在存储升级边界读取一次并转换为版本 2。升级完成后删除旧媒体记录；即使旧正文中的标记已被编辑删掉，仍按旧附件记录保留图片。消息发送和输入处理不再读取旧标记。

## 下载与外链

`Packages/ResourceLinks` 提供共享的下载和外链能力，不依赖 React 或 Vue。Android 的主控台和 QQ 文档使用同一个 `WebClientHost`，仅向已配对服务的主框架开放消息端口，在文档开始时注入能力。

- HTTP 下载交给系统下载管理器，仅对已配对服务附加该服务的 Cookie。
- Blob 和生成文件使用系统保存文件对话框，按固定上限分块写入，逐块确认；失败或文档关闭时清理部分文件。
- 外链通过系统 `ACTION_VIEW` 打开，启动失败返回明确错误，不依赖应用可见性查询结果。
- 浏览器使用同一公共 API 的浏览器实现。工作区资源继续使用实际服务地址及工作区参数。

## 连接与恢复

`ServerAuthenticationController` 是 React 与 Vue 共用的认证状态机，Cookie 和 CSRF 直接复用主控台会话。上传读取已建立的认证状态，不再逐附件请求 `/api/auth/session`。恢复时合并并发认证检查，网络暂时不可达保留已认证状态；明确的失效或拒绝需要用户重新登录。跨文档只广播认证状态失效通知，不广播凭据。

APK 同时打包主控台与 QQ 的入口、完整模块依赖和运行时表情资源，两个 WebView 都从同一配对源加载本地构建。`BundledWebClient` 只拦截构建清单声明的资源与工作区入口；API、上传、媒体和 WebSocket 仍请求电脑服务。QQ 不再加载电脑 Vite 文档或热更新客户端，避免开发连接断开触发手机整页重载。浏览器和桌面 dev 模式继续使用开发服务。QQ 的工作区元信息由服务端与客户端共用的文档上下文生成。

`ClientConnectionLifecycle` 统一文档可见性和 Android Activity 的暂停、恢复事件。健康的 WebSocket 在恢复时先验证连通性；重复恢复事件只处理一次，不刷新整个文档。失效连接按已有重连策略恢复并同步状态。

Android 的系统文件选择器属于当前文档的交互流程：选择期间不主动暂停 WebView，也不额外发送应用暂停／恢复事件。真正退后台仍执行原有的连接缓存与恢复；系统回收进程则按持久草稿恢复。选文件本身不执行导航、重载或重新登录。

主控台、QQ OneBot 连接及 QQ 控制连接统一使用 `createClientWebSocket`。浏览器使用浏览器 WebSocket；Android 通过已配对源的消息端口交给 OkHttp，握手复用该服务 Cookie、Origin 和正常 TLS 校验，禁止跨源或重定向。传输层 ping/pong 不依赖 WebView 计时器；应用层探活继续共用原有逻辑。

Android Activity 暂停后，原生连接继续收取事件并暂停向文档投递。事件缓存有字节数和条数上限，超限主动断线，恢复时走原有重连与历史同步。缓存不会无限增长，不会静默丢帧后继续声称连接连续。文档导航或 Activity 销毁时关闭其原生连接，避免旧文档事件进入新文档；前台服务降低进程回收概率，并不使已销毁的 Activity 或文档继续存在。

QQ 时间线用持久化的序号及版本游标分页追赶，消息、撤回和戳一戳共用顺序。删除、清空或注释变化使旧快照失效，客户端重新同步；没有变化时返回空增量。完整历史仍按向前分页读取。恢复不重放实时通知。

Android 仍可能回收后台进程。这种情况下恢复已保存的导航位置和消息草稿；尚未读取到网页的系统文件选择结果无法恢复，会提示重新选择。应用不会以后台常驻服务承诺无限保活。

QQ 最近会话从同一工作区的持久消息与事件时间线恢复；仅有通知的会话也保留。恢复不会重放通知或增加未读计数，异步响应不能覆盖更新的实时消息。打开或恢复聊天统一关闭侧栏遮罩，避免输入框继续受侧栏状态禁用。“重新编辑”显式接管草稿，旧的存储读取不能覆盖编辑内容。

Android 自动连接在启动窗口进入前台后打开客户端，并识别同任务内仍存活的聊天窗口；外部文件选择器位于栈顶时，不再重复打开客户端。冷启动恢复连接使用独立等待状态，认证或网络错误后才显示连接表单。
QQ 文档也区分初始化／自动连接恢复与主动连接表单，避免重建文档时在已保存连接恢复之前短暂展示登录界面。正常 OneBot 重连保持已打开的会话和草稿。
