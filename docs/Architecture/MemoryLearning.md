# 记忆学习与上下文边界

每个工作区、Agent UUID 使用独立的学习存储。MemOS 保管语义节点、向量和关系图；宿主 SQLite 保管原始来源、任务归属、证据、送达凭据、效用评估与版本化快照。模型不能直接修改计数或可信度。

## 任务效用与权重

记忆权重从 50/100 开始。已完成且有帮助的不同任务数为 h，妨碍任务数为 u，
权重为 `100 × (1+h)/(2+h+u)`。首次有帮助的任务完成后约为 66.67，之后为
75、80，增量逐渐缩小并趋近 100。它表示保留优先级，不表示事实为真的概率。
未使用、不确定和待评估各自计数，不改变权重；明确纠正通过 supersede 保留版本关系。

召回次数只统计模型实际收到记忆的不同任务。预览、SDK 读取、同任务多轮和重试
不重复计数。宿主先登记待送达选择，收到模型响应后确认送达；完成请求登记与
新知识提取分开，即使没有新记忆也会评估已送达内容。遵循偏好或据此回答问题
算有帮助，不要求用户再重复该偏好。同一任务按原始请求顺序保留最新有效使用
结果；未使用的跟进不会覆盖之前的实际使用。模型不再生成逐字证据校验与支持、
反证分数，但新知识仍需来自实际用户陈述或工具来源，不能用助手自述证明自己。

任务完成、效用结算与待同步节点保存在 SQLite。相同节点的变更合并为一个带版本
的后台项，失败保留待办且不阻塞其他节点。MemOS trust 统一为 1，权重只由宿主
计算并应用一次。评估通过事务替换，失败保留原结果。删除来源撤销对应贡献。

## 自动召回保留期

偏好与关系不按时间自动过期。事实提取完成后，另发一次 Pi 结构化请求，根据
当前用户意图、事实内容、近期上下文与实际来源选择保存天数，只输出 `days`，
不输出 reason。零代表不按时间过期；没有足够依据决定其他期限时，采用
`ContinuityLearning.Retention.FactDays`，默认七天。第二次调用沿用 Pi 的
Native/BAML 契约、预算与后台重试；失败记录在独立 `semantic_retention` 阶段，
不写入未经决策的永久事实，重试复用已完成的提取结果。

`Retention.ContextDays` 默认一天，控制任务上下文作为历史经历参与跨任务召回
的期限。原会话恢复同一任务时仍可读取它的工作状态，但不会恢复已被取代的版本。
到期仅停止自动召回，保留显式历史查询；删除来源仍会清理相关知识。召回、增权、
重启和 SDK 更新都不续期。旧记录按原始内容时间迁移，不从升级或读取时重新计时。

## 稳定背景与任务上下文

生产运行时的记忆主体来自宿主身份注册表，与会话 ID、昵称及渠道号码分开。
个人自动召回、精确引用读取、学习历史窗口、近似重复分组和日记读取都按主体隔离。
原控制台主人及本地操作者的旧主体键仅在宿主能证明关联时保留为别名；新学习使用
持久身份。缺少认证来源的旧外部账号不会被自动合并到某个人，避免将历史歧义当成授权。

用户和 Agent 的公开引用采用资源身份共用的六位小写编码规则。注册表位于
`.senera/data/identities/references.sqlite`，按身份领域独立分配和解析；相同短码在不同领域互不代表同一主体。
旧用户引用作为精确别名保留，既有 UUID、账号绑定和记忆归属保持不变。短码用于识别与查询，不作为认证凭据。

每轮按当前问题检索候选，偏好、事实、关系和历史任务经历都由已配置的记忆模型判断是否
能帮助当前请求。仅泛泛的话题相似不算相关；通过评估后，使用 `相关性 × 权重 / 100`
排序。MemOS 原始关键词与向量分数保留为检索依据，SDK 含可信度的 hybrid
分数不再重复乘入宿主排序。全局偏好另有少量保留预算，不要求与开场问题匹配；
合并时按节点 ID 去重，真实问题评估覆盖全局投影，不能用无查询扫描结果替换
问题匹配分。无查询载入不冒充词法、语义命中或问题相关性。

相关性评估按模型输入预算分批，Native 与 BAML 共用结果契约。评估结果以模型配置、问题、原文和契约摘要保存在请求账本中，相同输入可复用。冻结版本无需逐轮重评，动态候选继续按本轮问题筛选。失败明确记录并展示，未经评估的普通知识不注入；已有冻结背景仍保留。没有问题文本时不推断普通事实的相关性。

冻结背景预算比例由 `Recall.FrozenBudgetRatio` 配置，默认 0.25；日记标题索引能在总预算内整块优先保留。当前任务预留比例由 `Recall.TaskBudgetRatio` 配置，默认 0.5，两者之和不能超过 1。剩余动态空间供任务状态与相关知识共同使用。记录按优先级、时间与稳定身份排序，长度只决定能否整条放入。当前任务按 sessionId 与 taskId 隔离，排序取问题相关性、任务内相对新近程度和权重的算术平均；没有查询命中的记录相关性为零。未完成步骤与待办来自现有执行状态，不从摘要关键词猜测。预算按实际序列化文本计算，并受当前模型可用上下文限制。

system 冻结偏好、日记标题索引以及选入时的排序分、依据和权重。成功的空结果同样冻结，重启保留；新会话或压缩才重选。liveContext 分开携带当前任务状态与相关知识：后者能跨可访问对话检索事实、关系、冻结版本未覆盖的偏好与历史经历。历史经历明确标记为参考，不能证明当前任务已经完成。当前任务跟随会话和话题，状态卡从本次提供的持久任务引用中选择旧任务，支持中途换题后回来；引用不能越过会话或发言人边界。存储读取与评估失败均可重试，不伪装成成功的空结果，也不清空已有冻结背景。详情继续使用 MemoryRecall。

Pi 成功提交原生压缩摘要后，以压缩 entry ID 幂等推进快照版本，用当前问题和已提交摘要重新召回，在下一次正常模型请求中替换宿主系统背景。平台真理、其他扩展提示与工具声明保留；Pi 自己生成摘要的请求保持其原生提示。异步刷新不能覆盖下一轮已租用的会话。

## Markdown 日记与月记

日月摘要由文件保存，不再写入 MemOS。每个工作区的 Agent UUID 对应
`.senera/data/agents/<uuid>/diary/subjects/<base64url主体ID>/`，日记位于 `YYYY/MM/DD/diary.md`，
月记位于 `YYYY/MM/diary.md`。正文是一级标题和 Markdown 内容；旁边的
`.diary.json` 只记录生成版本、内容摘要与原始来源，供重启恢复和删除处理使用。

索引、日记和月记只使用同一主体的来源。模型的 `senera diary` 调用绑定当前发言人，
人工 CLI 默认工作区主人；模型不能通过命令参数选取其他用户。旧的混合目录保留为
迁移材料，自动索引不以它充当私人日记。删除来源会同时失效各主体的派生文件。

自然日结束后，宿主读取当天已完成的物理回合，分别提供用户消息和助手最终回复的
预览，并附上已提交的记忆片段及实际权重、已知主体和记忆学习状态。
预览复用模型 tokenizer，`Diary.TurnPreviewTokens` 默认每段 128 tokens，
不复制到 MemOS 知识或向量索引。助手的完成声明不作为工具执行成功的证据。
有权重的回合优先，再按实际权重、完成时间和稳定身份排列；在输入预算内选择
材料，复用 Pi 结构化模型调用生成 `title`、`body` 两个字段。
Native 必需工具输出与 BAML 使用同一校验契约；正文完整保存，不再套用短记忆
片段的长度限制。`ContinuityLearning.Diary.InputTokenBudget` 默认及最大值为
32768 tokens，连同输入结构、指令和输出契约计算，模型窗口较小时继续服从 Pi
的上下文预留。末条材料可缩短文本字段，仍保留角色和状态；宿主完整保留来源，
输入明确报告未选回合数量，学习状态统计覆盖所有来源回合。

月记只在月份结束后生成。输入是每天标题和正文开头最多 512 tokens，截断才
追加 `...`；完整输入超过预算时，保留所有标题并均匀缩短正文预览。
某日日记生成失败时，该月等待补算，其他日期继续处理。重启补齐已结束的日月，
逐轮恢复记忆提取。跳过、待处理或失败的记忆学习不阻塞该日及月份的生成，
模型仍可按明确的学习状态概括问答预览。后续学习提交会改变来源版本，刷新对应
的已结束日期。
日记生成与记忆提取共享模型并发额度。
相同来源版本不重复请求模型。日历时区由 `Diary.TimeZone` 配置，按照实际日界
和月界处理，不用固定小时数代替自然日。

日记标题以 Markdown 索引进入 system 的长期背景，默认取冻结时前七个已结束
自然日。索引与记忆快照一起持久化，即使长期知识为空也会保存；跨天、日记更新
和重启不会改写当前版本，新会话或 Pi 压缩后重新选择。索引不包含正文，完整
文本计入背景预算；窗口不足时整块不注入，持久化快照仍保留原索引。
模型先根据标题选择日期，需要最新目录或正文时通过 `senera CLI` 查询：

```text
senera diary list
senera diary list 2026-10
senera diary read 2026-10-26
senera diary read 2026-09
```

模型调用自动绑定当前 Agent；人类 CLI 可以在最后指定 Agent UUID。
日记是整理后的历史叙述，不能作为提高可信度的独立证据；具体事实与来源仍使用
MemoryRecall。旧 MemOS 摘要先导出再退出数据库权威存储。删除来源会清理受影响
日记及其月记，并阻止生成中的旧结果回写；删除 Agent 连同整个日记目录一起删除。
删除请求在等待提取任务之前持久化。来源清理完成后，日记重建作为独立后台任务
处理；模型服务暂时不可用时，不会把已完成的来源删除误报成失败。

## 身份与升级

主控台主人及渠道发言人使用宿主持久化的 UUID，短引用供模型区分发言人。渠道原生账号
按适配器认证来源绑定；官方 QQ 的 OpenID 另按 AppID 隔离，不能自动视为工作区主人。
自动召回、显式查询、精确引用读取与学习更新均校验主体归属，任务状态还校验任务 ID。
旧知识没有可靠归属时保留在 MemOS 供人工迁移，不开放给任意当前发言人，也不猜测身份。
学习输入明确携带本次主体，群聊中其他人的陈述不能被转写为当前用户的偏好；历史窗口和
日记材料使用回合记录的发言人称呼，不用当前主人的资料替换其他用户的姓名。

启动迁移仅根据精确 episode、来源 URI、request ID 及已验证的任务绑定恢复旧记录归属。所有支持来源必须可追溯且身份一致；缺少来源、混合发言人或绑定冲突时不回填。只有会话 ID、对话名称或消息文本不足以证明身份。迁移不制造可信度证据。连续性事件的生产、实时消费与历史回放共用浏览器安全的 Zod 契约，面板同时展示长期背景、任务记忆和未注入原因。

宿主数据库 migration 6 新增证据与评估账本、任务绑定和快照版本表。升级保留原始对话、来源和 MemOS 节点，只移除无法证明归属的旧派生快照；下一次提示边界会重建。删除来源同时清理跨会话快照，防止已删除内容被缓存或并发召回重新写回。

migration 7 在快照中保存日记索引。已有版本保留原背景，在下一次新会话或压缩
边界才捕获目录。连续性面板的排序分与相关性汇总由后端从实际选入记录生成，
相关性只统计真正带评估分的记录，不以排序分补齐缺项。面板分别展示选入时的
冻结质量与本轮准备时的当前账本，后者包含综合加权分和已结算召回任务数。
冻结排序不会因后台增权而改写；新会话或压缩边界使用最新账本重新选择。
自动召回直接记录检索、相关性评估、任务记忆及总耗时，声明本轮是问题检索、
无查询偏好选择还是冻结复用；不依赖旧的召回审计事件。界面不展示资源 URI。

migration 8 新增任务完成记录及节点同步待办。已有完成请求仅在确实存在
任务绑定与送达凭据时参与增权，不凭摘要猜测历史召回。启动也会补齐已落盘、
但尚未来得及通知后台的完成请求；业务未完成的任务不会提前加分。

migration 9 退役独立证据评分，保存历史效用审计并统一权重职责。
migration 10 一次性清除派生背景快照，按偏好冻结、知识动态召回的新约定重建；
原始对话、来源、MemOS 节点与文件日记保留。后续仍遵守正常冻结边界。

Agent 数据库按需打开时，迁移可能晚于服务就绪检查。就绪后的迁移在开放业务
写入前提交升级记录；启动阶段的迁移仍等待就绪检查统一提交。这样重启恢复不会
把已运行的 Agent 账本错误回退到迁移前的备份。
