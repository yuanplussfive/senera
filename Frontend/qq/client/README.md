# Senera QQ 客户端

这是 Senera 可选 QQ 客户端的页面源码。依赖由 `Frontend/package.json` 声明，
由仓库根目录的 `package-lock.json` 统一锁定，不再维护独立 npm 包。
第三方来源和许可证保留在 [NOTICE.md](NOTICE.md) 与 [LICENSE](LICENSE)。

## 开发与构建

在 Senera 根目录执行：

```sh
npm ci
npm run dev
```

主控台「渠道」打开的是已安装扩展。开发源码时，在工作区客户端路由后添加 `development/` 显式打开 Vite 页面；修改 `src/renderer/src/` 后可热更新，该入口只在开发宿主启用。
网页端在独立标签页打开，桌面端在独立窗口打开；同一工作区的桌面窗口会复用并聚焦。
关闭 QQ 窗口不影响主控台。QQ 页面独立管理外观，聊天、附件和事件仍走工作区的真实渠道接口。
桌面 QQ 窗口不注入主控台 preload，保持浏览器隔离与系统外链打开策略。
QQ 页面和主控台共用 `Frontend/vite.config.ts` 与同一个 Vite 开发服务；
消息、WebSocket、附件和鉴权仍在后端工作区地址，不经过另一个网关代理。
消息接收时按宿主页面地址解析媒体 URL，避免开发环境的静态资源 `<base>`
把图片、视频或文件请求导向 Vite；历史重放、引用预览使用同一解析入口。
Markdown 中的工作区路径、行列定位、资源 URI 和下载均复用 `@senera/resource-links`，
与主控台使用同一份资源协议。图片走当前工作区资源接口并使用 QQ 图片查看器，
文件下载携带宿主登录态；普通网页链接保留原标签且独立打开。
`desktop.live` 自动将实际前端开发地址传给桌面宿主，支持动态端口。

发布运行 `npm run client.qq.pack`。QQ 独立构建，自带完整运行时依赖；认证、上传、草稿和消息仍直接引用主控台源码。基础桌面包、镜像和 APK 不包含 QQ 页面与表情。

## 发布资源

源码唯一位置是 `Frontend/qq/`，构建目录由 `AgentQqClientBuild` 声明。输出为 `Release/SeneraQQ-<版本>.zip`、描述文件和对应源码包。在「设置 → 渠道 → Senera QQ」安装或导入 ZIP；扩展在电脑的应用数据目录安装一次，供所有工作区、桌面与连接的手机共用，同源认证不变。渠道配置、会话与附件仍属于各自工作区。

清单声明入口、资源大小、摘要和宿主协议版本。安装器先校验再切换版本；已打开的页面继续读取自己的版本资源。资源清单在运行时缓存，不在每个图片请求上重复执行校验。卸载不删除会话和附件。

对应源码包保留实际目录、构建脚本、依赖声明和根锁文件。解压后执行 `npm ci`、`npm run client.qq.pack`；类型检查使用 `npm --workspace senera-frontend run check.qq-types`。页面从宿主的许可证元数据读取对应源码地址，不能根据静态资源目录拼接。

构建和打包均检查源码指纹。发布源由产品元数据配置，设置中显式更新或导入客户端，不运行另一套更新器。打包、PR 构建和 Android 签名详见[可选客户端说明](../../../docs/Development/OptionalQqClient.md)。

## 消息与时间

消息正文与原生消息段保存在工作区 `.senera/onebot11/data/messages.sqlite`，
媒体文件保存在 `.senera/onebot11/media/`。同库时间线记录戳一戳、撤回通知、
重新编辑所需的原消息及宿主提供的任务关联。浏览器刷新后从宿主重新加载，
不在浏览器外另建一套客户端历史数据库。

时间持久化使用 UTC 时间点，OneBot 使用 Unix 秒；所有界面时间和日期分组
使用宿主声明的 `Asia/Shanghai`，不按浏览器所在时区漂移。

清空对话同步关闭主控台会话并更新渠道会话代次；删除任务或撤回自己的消息
沿用主控台的历史截断，删除该任务及后续内容，包括该任务发送的多条消息。
模型主动撤回自己发送的一条消息仍使用 OneBot 单条撤回，不反向终止正在执行的任务。
旧消息缺少可验证的任务关联时拒绝按任务删除，不根据时间猜测归属；仍可清空对话。

## 上传与连接恢复

图片预览使用本地对象 URL，发送时直接上传原始文件；不自动压缩、不经过 Base64
往返转换。QQ 与主控台共用带鉴权的 multipart 资源上传接口，OneBot 只发送资源引用。
图片编辑产生的新文件也走同一上传入口；移除附件、切换对话或关闭界面会释放本地预览。

手机打开文件选择器、切到后台或短暂断网时，聊天界面和当前图片草稿保持挂载。
心跳超时与身份失效使用不同的关闭原因：前者在回到前台时探活并重连，后者要求重新登录。
上传请求不因协议连接暂时断开而取消；上传完成后等待协议握手成功再发送。
已发出但未确认的消息不会自动重发，避免重复发送。网络上传本身失败时明确报错并保留图片草稿。

电脑上的 Agent 任务和消息存储不依赖手机在线。Android 可在用户启用后运行后台连接前台服务；
系统仍可能暂停 WebView 网络，恢复后从工作区的持久化时间线同步消息，
不通过延长心跳超时来假装持续在线。

## 维护边界

页面通过宿主登录态连接 OneBot 11 与控制台事件流，两个连接共用前后台监听与重连策略。
保留已认证的聊天界面、上传与草稿，握手成功后再恢复发送；身份失效则明确断开。
协议映射直接使用 OneBot 11 契约，不按服务端品牌名称猜测协议。
表情资源随可选扩展发布，拼音检索从锁定的 `pinyin-pro` 依赖按需加载。
旧独立客户端的欢迎向导、推广、遥测、自更新、原生平台桥接与无引用的样式已移除。
工作区设置读取与宿主初始化共用存储解析器，并保留原有存储键，避免升级丢失用户设置。
