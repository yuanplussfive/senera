# Android 客户端

Android 应用复用 `Frontend` 的 React 主控台、公共组件和响应式布局。`Frontend/mobile/index.html` 是设备连接入口，连接成功后加载同一主控台。电脑继续运行 Agent、终端和浏览器；手机只负责提交任务、审批和查看结果。

## 连接和登录

- 连接方式可选：**局域网直连 / HTTPS 地址 / 私有网络**。主控台根据当前 HTTPS 来源和实际网卡地址给出建议，不自动安装网络工具、不在失败后切换连接方式。
- 局域网：电脑账户菜单 → **连接手机 → 局域网**，选择手机可访问的网卡和端口，明确开启入口。手机与电脑连接同一 Wi-Fi 后扫码。HTTP 仅允许私有 IPv4 地址，适用于信任的局域网；可随时关闭入口，关闭也会断开对应连接。设置随应用保存，重启后恢复；地址已变化时保留错误信息，等待用户重新选择。
- HTTPS：使用已部署且手机可访问的域名。通过 HTTPS 打开的主控台可直接识别当前来源，也支持保存自己的地址。
- 私有网络：用户选择后才检查 Tailscale；电脑与手机加入同一网络后可明确启用 Serve。已有服务或 Funnel 冲突时报告原因，不覆盖现有配置。Tailscale 是可选项，局域网不依赖它。
- 账号密码登录：使用已配置的管理员账户，填写所选入口的完整地址。没有管理员账户的本地电脑可直接扫码配对，不要求先创建账户。
- 扫码登录：选择连接方式并生成二维码后，手机选择 **扫码登录**，扫描后由电脑明确允许该设备。
- 二维码有效五分钟，仅可消费一次。二维码、扫码凭证、审批者会话和领取凭证绑定；审批者退出、二维码过期或重建都会使原配对失效。二维码不包含密码或长期设备会话。
- 主控台的 **连接手机 → 已连接设备** 可撤销设备。撤销后 HTTP 请求和现存 WebSocket 的后续消息都会被拒绝。
- 原生凭据使用 Android Keystore 加密存储。HTTPS 设备使用独立 Secure/HttpOnly/SameSite=None Cookie；明确启用的局域网使用独立 HttpOnly/SameSite=Strict Cookie，不共享跨站 Cookie。上传、图片、文件、WebSocket 和 CSRF 校验共用现有主控台链路。
- 手机可保存多台电脑；按服务地址隔离凭据和工作区偏好。切换电脑位于账户菜单。

电脑必须持续运行，手机必须能访问所选服务。扫码不负责网络穿透。局域网入口复用主程序的 HTTP/WS 路由和鉴权，单独绑定用户选择的接口；外部请求不会继承 loopback 免登录权限。公网连接使用可信 HTTPS，证书验证不会被关闭。局域网 HTTP 的安全上下文 API 仍受 WebView 限制。

手机登录请求使用有超时和响应体上限的原生传输，区分 DNS、连接拒绝、网络不可达、超时、证书验证、重定向、非 Senera 响应及授权错误。超时只说明未收到响应，提示同一 Wi-Fi、防火墙或设备隔离等检查方向，不伪造确定诊断。

设备会话沿用主服务的绝对/空闲有效期，服务重启后重新登录。系统后台暂停不会取消电脑上的任务；返回前台会检查现有连接，并通过原有历史恢复链路同步。未接入后台推送服务。

## 后台与悬浮窗

手机连接页及主控台账户菜单均提供 **后台与悬浮窗** 入口，默认关闭，不在安装或扫码时批量申请权限。

原生设置页按后台连接、悬浮入口与系统权限分组，适配系统深浅色；通知、电池权限直接读取系统状态，返回设置页立即刷新。未开启后台连接时，悬浮入口显示启用条件。已获电池豁免后仍可进入应用详情管理该权限。

- **后台连接**：用户启用后运行 `connectedDevice` 前台服务，显示可停止的常驻通知，保留持有现有 WebView 连接的应用进程。服务监听实际网络变化，不再建立另一套消息连接，不启动定时轮询、不长期持有 CPU 唤醒锁。
- Android 13 及以上会在开启时请求通知权限。用户可从通知中停止后台服务；从最近任务划走应用也会停止。服务不会从开机广播或系统后台静默重启。
- **电池优化**：通过系统面向本应用的授权界面，允许用户选择是否豁免。部分厂商仍需在应用详情中手动允许自启动、后台活动；不使用按品牌拼接的私有设置地址。
- **悬浮入口**：开启后台连接后可单独授权显示在其他应用上层，出现可拖动、点击返回 Senera 的入口。悬浮窗不读取其他应用内容，也不是后台保活权限。

前台服务和电池豁免只能减少后台限制；网络切换、系统进程回收、用户强制停止等仍会中断连接。电脑上的任务继续运行，恢复应用后同步结果。

## 本地构建

需要 Node 24、JDK 21、Android SDK Platform 36；Gradle 按 Android 插件版本安装匹配的 Build Tools。扫码插件使最低版本为 Android 8.0。安装并更新 Android System WebView；实际兼容范围还取决于前端采用的 Web API。

设置 `JAVA_HOME`、`ANDROID_HOME`（或 Android Studio 的本地 SDK 配置）后，在仓库根目录运行：

```sh
npm ci
npm run mobile.android
```

命令会构建共享前端、同步 Capacitor 插件，先通过对应构建变体的 Android Lint 兼容性检查，再生成 debug 签名 APK，输出 `Release/Senera-<版本>-android-universal-debug.apk`。无需给手机打包 Node、Electron、模型密钥或电脑工具。编译 SDK 较新不意味着运行设备支持同一套 Java/Android API，禁止跳过最低版本兼容检查。

打开 Android Studio：`npm --workspace senera-frontend run android:open`。

发布 APK 使用 `npm run mobile.android.release`，签名通过以下环境变量提供，不写入仓库：

| 环境变量                        | 用途               |
| ------------------------------- | ------------------ |
| `SENERA_ANDROID_KEYSTORE`       | 私有签名库绝对路径 |
| `SENERA_ANDROID_STORE_PASSWORD` | 签名库密码         |
| `SENERA_ANDROID_KEY_ALIAS`      | 签名别名           |
| `SENERA_ANDROID_KEY_PASSWORD`   | 私钥密码           |

没有发布签名时命令不会把 unsigned APK 当作可安装发布版。应用版本来自根 `package.json`，不要在 Android 工程单独维护版本。

基础 APK 仅携带主控台。Senera QQ 使用独立扩展包，在「设置 → 渠道 → Senera QQ」安装或导入后，在独立 WebView 中加载配对电脑上的已安装版本。共享认证、附件、草稿和原生消息端口，手机端不加载 Vite 热更新客户端。扩展依赖随自身版本分发，由 WebView 缓存；不需要另装 QQ APK。对应源码和许可证随扩展交付。

ARM64 APK 使用 `npm run mobile.android -- --abi=arm64-v8a`；已有前端构建使用 `npm run mobile.android.from-build`。扩展打包、PR 构建产物、正式签名配置见[按需安装的 Senera QQ 客户端](../../docs/Development/OptionalQqClient.md)。

局域网主控台使用同样受限的宿主端口，直接在配对来源下加载 APK 内的同一套主控台资源，因此 dev 服务无需额外托管前端；API、多媒体和 WS 仍连接电脑。主窗口保持 HTTPS 本地来源并禁用混合内容；局域网 WebView 拒绝其他来源的明文资源。

Android 工程是受维护源码；`cap sync` 生成的绑定、前端资源、SDK 路径、构建产物和签名密钥不提交。扫码使用官方插件的 ZXing 模式，不需要 Google Play Services 扫码模块。未接入 FCM 或额外通知账户。
