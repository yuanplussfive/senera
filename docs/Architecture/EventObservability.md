# 事件观测架构

Senera 的事件观测面板用于诊断当前浏览器连接能看到的真实运行过程。它统一展示 WebSocket 连接生命周期、客户端命令和后端领域事件，但不是原始载荷抓包器，也不替代服务端持久日志或 OpenTelemetry。

## 数据链路

```text
后端领域事件
  -> AgentEventCatalog（layer / phase）
  -> AgentEventObservationCatalog（浏览器保留策略）
  -> 生成 Frontend EventSpecs
  -> WebSocket
  -> agentTransportObserver
  -> 有界 Event Journal
  -> 洞察工作坞的原始日志页

客户端命令 / 连接状态
  -> agentTransportObserver（只有类型、关联 ID、状态和大小）
  -> 有界 Event Journal
```

认证准备流程会先安装 Event Journal recorder，再渲染主工作台或独立设置页。所以两个界面建立的 WebSocket 都进入同一个观测边界，首批连接和命令事件也不会因 React effect 顺序而丢失。事件面板本身保持懒加载。

## 正式运行阶段

`run.activity.changed` 是后端正式领域事件，不是终端文案。每个阶段包含：

- `activityId`：阶段实例 ID。
- `parentActivityId`：异步父阶段 ID；根阶段省略。
- `activity`：由 `AgentRunActivities` 声明的稳定阶段名。
- `state`：`started`、`completed` 或 `failed`。
- `startedAt`：开始事件和终态事件共享的 ISO 时间。
- `durationMs`：终态事件的单调时钟耗时。

`AgentRunActivityReporter` 使用异步上下文传播父阶段。并发子任务共享正确父阶段，不依赖进程级可变栈，也不会把兄弟任务错误投影为父子任务。活动类别由 `AgentRunActivitySpecTable` 统一声明并生成给前端。

工具生命周期也必须携带明确的时间边界。`tool.call.started` 使用后端采集的
`startedAt`，`tool.call.completed` 和 `tool.call.failed` 使用同一 `startedAt` 以及后端测量的
`durationMs`。浏览器诊断只消费这组字段；没有完整时间边界的历史记录仍可在技术事件视图中查看，
但不会被拼成一条时间段。

Pi collector 与普通 `AgentToolCallExecutor` 共用 `AgentLifecycleClock`：墙上时钟只负责生成
`startedAt`，单调时钟只负责计算 `durationMs`。这样系统时钟回拨不会制造负耗时，也不会让前端用
WebSocket envelope 的接收时间代替后端测量。

## 对话过程恢复

思考通过 `model.thinking.completed` 保存完整块，包含模型消息位置、内容位置及完成或中断状态，逐 token
增量不落盘。普通历史与压缩窗口按本页请求和事件快照边界读取完成任务的思考块，先在存储层筛选再分页；
失败、取消和活动任务沿用已有执行事件恢复。工具详细结果与诊断仍按需读取。

主对话的执行过程同时保留思考与工具步骤。具有模型阶段坐标的记录沿用原阶段顺序，旧精简轨迹缺少坐标时
按轮展示思考，不猜测其所属工具阶段。重复回放按思考块身份合并；运行中刷新保留实时块，同时补回先前已
持久化的块。完成、失败和取消状态不会因为恢复思考而重新进入运行状态。

历史回放与实时事件复用同一投影和去重逻辑，并明确标记来源。长历史分片恢复时，每次让出主线程前保留最新
实时状态；恢复期间到达的新增正文、思考以及完成或取消事件不会被恢复开始时的快照覆盖。

## 浏览器保留边界

`AgentEventObservationCatalog` 是浏览器诊断数据的安全边界。每个 `AgentEventKind` 必须显式选择：

- `metadata`：只保留事件类型、layer、phase、序号、时间和关联 ID。
- `projection`：额外保留声明的 RFC 6901 pointer。

需要在事件日志中作为过滤关联条件保留的 payload 标识，也必须在同一个 descriptor 中声明
`resourceIdPointer`；前端不会从 `data` 对象中按名称搜索 `resourceId` 或其他字段。

前端不按字段名猜测敏感信息。用户消息、模型增量、工具输出正文、工具结果、配置值、凭据和错误详情默认不会进入 Journal。新增事件如果没有保留声明，生成契约会失败；前端不能临时增加另一套字段白名单。

Journal 的阶段投影只接受事件目录中带有 `diagnostic` descriptor 的生命周期事件。descriptor 由后端
`AgentEventObservationCatalog` 声明并生成到独立的 `generatedRuntimeDiagnosticCatalog`，包含来源、身份
指针、标签指针、状态指针或固定状态、开始时间指针和耗时指针。前端只按这个 descriptor 读取 RFC 6901
指针；没有 descriptor、指针值不完整或身份不一致的载荷直接拒绝，不扫描未知 payload，不按字段名猜测，
不用相邻事件时间戳补齐 `durationMs`。诊断 descriptor 只进入懒加载的诊断工作坞，不增加主应用的事件
目录负担。

出站命令只保留请求类型、安全关联 ID 和序列化大小，不保留请求正文。可选 raw-frame 模式只记录方向和帧大小，不保留帧内容。投影超过 64 KiB 时整份省略，不做可能误导诊断的局部截断。

## Journal 生命周期

Journal 是独立于会话状态的内存 store，默认记录并应用以下硬上限：

- 最多 2,000 条记录。
- 最多 2 MiB 实际保留数据。
- 最长 30 分钟。
- 单个声明式投影最多 64 KiB。

网络上观察到的帧大小和 Journal 实际保留大小分别计量；一个超大但未保留正文的请求不会错误驱逐整个日志。停止记录、暂停视图、开启 raw-frame 元数据和清空记录是四个独立操作。刷新页面会清空 Journal，不做跨会话持久化。

## 运行诊断视图

洞察工作坞由 `SessionInsightsPanel` 统一选择轮次，分为概览、上下文和事件三页。概览汇总会话统计、用量、耗时、
上下文趋势和调用记录；事件页使用会话 store 中的真实步骤，工具的参数、失败原因和结果共用 `ToolStepInspector`。
上下文页按模型请求查看分类组成、请求变化和完整输入内容；概览趋势和事件页中的模型项可以直接定位到对应请求。
记忆注入与召回由连续性面板展示，洞察概览不重复挂载上下文正文浏览器。

连续性默认展示紧凑的类型分布、记忆注入预算与检索计数，下面按冻结背景、当前任务、相关知识分组展示原生
记忆表格。表格列出内容、类型、当前权重与召回任务数，支持内容与类型筛选，以及权重、召回次数排序；恢复
默认顺序时沿用宿主选入顺序。缺少质量记录时显示未知，不把选入排序分转换为权重。记录展开后展示来源、
保留时间、有效任务等属性，详细评分和账本对比按需展开，对比只列变化项。召回诊断默认收起，展开后挂载。
记忆正文只显示一次，所有评分直接读取宿主数据；记忆与洞察的标题计数共用圈注数字。放大、收起保留筛选、
排序、展开项与滚动位置，切换会话或轮次后重置查看状态。

事件页将执行过程和上下文变化分开。执行轨迹采用按轮次与 Agent 范围组织的紧凑记录表，分别显示操作、结果
或实际输入量、状态与耗时。请求作为步骤边界，轮次与并行组可折叠。点选记录后，详情在独立滚动区复用
工具查看器；宽面板并排展示，窄面板展示在下方，展开结果不改变记录行高度。
初次打开只投影最近 50 条执行记录并定位尾部，更早记录按页展开。新记录追加时保留已有窗口；位于尾部时
跟随更新，向上翻阅或打开详情时停止跟随，提供返回最新记录的入口。搜索和筛选覆盖完整驻留历史，直接显示
匹配操作，不受折叠或最近窗口限制。请求编号与轮次统计同样保持完整历史语义。
固定时间概览按已记录开始时刻与耗时绘制模型、工具两条时间轴，点击可定位记录并打开详情；尚未结束的记录
只显示开始标记，不估算结束时刻。相邻且由宿主声明为并行的调用，在首条操作同行显示并行数量与折叠入口，
保留组内失败数量与运行状态；折叠后保留首条操作，单项调用不标记为并行。
通用工具简介不作为本次操作的目的，未声明的参数不自动拼入活动摘要。完整参数和结果继续复用工具详情查看器。

精简历史保留工具来源声明，并只提取声明的动作参数路径。动作预览最多 4 KiB，单个文本叶子最多 256 字节；
原始提示、工具结果和未声明参数不会进入统计接口。完整参数与结果仍由已有运行详情链路读取。已请求的
统计分页在切换面板内部标签后继续完成，切换会话才取消，避免留下无法结束的加载状态。

概览与事件页复用同一个上下文事件模型和行组件，新增、移除、模型切换分别展示；只有保存的宿主压缩事件
可以显示为压缩。快照差异的 token 数明确标识为估算，不把内容减少推断为发生压缩。

洞察历史使用 `/api/session/insights` 的稳定快照和游标分页，按页投影后释放原始事件；刷新、任务完成和重新进入
已访问会话时只读取已扫描游标之后的记录。中断的分页先完成原快照，再补读离开期间的新增事件。读取和投影均可
取消，切换会话立即取消旧任务；面板仅缓存最近三个服务地址与会话组合，淘汰后仍可从服务器重建。

洞察订阅只追踪步骤、计量、状态等观测字段，模型正文和思考流增量不会触发统计重算。未变化轮次复用已合并结果，
分类组成和快照比较按不可变快照弱引用缓存；事件列表只比较当前展开的记录，趋势按执行范围单次遍历。
历史投影交给共享空闲调度器分批处理，新会话先显示壳层，统计更新使用 React 的可中断渲染。

过程与上下文页共用 Agent 范围筛选，身份来自执行 scope，不以 Agent 名称去重。同名子 Agent 的请求、工具
和计量保持独立；筛选后只累计该范围实际记录的请求用量，缺少计量时显示未知，不借用整轮总量。上下文变化
与同一执行范围内的上一次请求比较，相同内容出现多次时逐项计数，可单独查看本次新增内容。

搜索、筛选、展开项与当前请求只用于关联的会话与轮次，切页或放大时保持，不套用到其他会话或轮次。正文读取
复用工作区资源认证与查看器，支持复制；只保留当前轮次最后一次打开的正文，按服务地址与不可变资源 URI
匹配，避免放大后重复请求或跨服务复用内容。正在加载历史时保留已到达的步骤，明确显示加载状态。

`AgentPiContextInspection` 在输入准备完成后捕获 Pi 输入，Native 与 BAML 共用同一份快照合同。
Native 快照表示供应商序列化前的输入，BAML 快照表示编译前输入，两者均不冒充供应商的最终 HTTP 报文。
快照按 Pi 的真实内容块区分系统提示、工具定义、用户消息、思考、预回复、模型回复、工具调用与工具结果。
同一模型消息中的思考与调用分别记录，与工具调用一起输出的文字归入预回复，其他文字归入模型回复；
相邻同类内容块合并，每次工具调用单独保留其名称与调用身份。分类只影响观测快照，不改变模型输入。
列表、筛选、分类统计与变化事件共用分类合同，旧快照保留原分类，新请求会对已有消息重新捕获。
各分类的 token 数使用本地估算；请求总输入优先显示该次请求的
供应商用量，历史请求不会借用当前会话的仪表值。BAML 无供应商计量时保留估算来源。

正文通过既有资源发布与读取链路保存，`model.started` 仅携带分类元数据和资源索引。相同会话中未变化的正文
按内容身份复用；存储与供应商传输并行，事件 collector 等待资源保存后发布索引。读取正文按需展开，自动加载并
支持错误重试；正文中的图片二进制明确省略。执行和内容列表使用虚拟滚动，放大视图使用双栏布局。旧记录未保存
输入快照时明确显示不可还原，不从当前状态猜测补齐。原始日志入口保留 Journal 的过滤、暂停和结构化详情能力。

## 扩展规则

新增或修改事件时按以下顺序维护：

1. 在后端事件类型和 `AgentEventSpecTable` 中声明协议。
2. 在 `AgentEventObservationSpecTable` 中明确浏览器保留策略。
3. 如有新的运行阶段，在 `AgentRunActivitySpecTable` 中声明类别。
4. 运行 `npm run generate.frontend-events`，不要手改生成目录。
5. 为投影安全、阶段生命周期和前端展示增加行为测试。
6. 运行 `npm run verify.frontend-events`、`npm run verify.i18n` 和前后端测试。

事件详情只用于当前用户的本地诊断。需要跨进程检索、长期指标或分布式 trace 时，应新增独立的服务端观测 sink，而不是放宽浏览器投影或把原始载荷写入 Journal。
