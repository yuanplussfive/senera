# 工作区宿主

工作区是服务器可访问的普通目录。应用宿主只持有目录登记、共享传输和安装级资源；配置、MCP 凭据、embedding、模型目录、推理预算、会话、项目记忆、上传和执行资源都归属于选中的工作区。打开另一个目录会先准备目标运行时，切换确认送达后按现有运行时停止链路回收旧运行时；停止会话、Pi、MCP、观察器和调度资源，但持久化数据保留。

应用目录由 `env-paths` 按平台解析，部署可以显式设置 `SENERA_DATA_ROOT` 或传入 `applicationStateRoot`。工作区登记在应用目录的 `.senera/workspaces.json`，配置和 MCP 凭据的宿主主密钥位于应用目录的 `.senera/keys`，本机所有工作区共用同一对密钥；工作区自己的 `.senera` 保存配置、会话、MemOS、编排数据库、Pi 会话、MCP schema、工具向量、文件观察基线、产物索引、插件、上传和导出。旧版本留在工作区里的密钥文件只读不写，包括更早期直接放在 `.senera` 根下的那份配置密钥，密钥环把它们当作候选密钥直接解密历史密文，因此迁移不再复制密钥。旧版本的宿主状态只在检测到旧源且工作区目标尚无对应状态时导入到工作区 `.senera`；源目录始终保留，目标已有文件优先，迁移只补齐缺失项，不覆盖或移动工作区数据。迁移清单只记录完成版本、源与目标路径和备份路径，旧版本产生的备份必须通过明确的维护流程清理。

项目指令、Skills、MCP、插件、上传、产物和用户导出的文件保留项目归属。Pi 复用 SDK 的项目指令发现，包括 `AGENTS.md`，并加入 `.senera/context/PROJECT.md`；文件内容变化会更新会话的指令指纹。推理预算和供应商配置由每个工作区自己的配置服务提供；当前 MemOS 仍是项目记忆，不会自动把不同项目的知识混在一起。

Skills 在模型服务创建前由同一个扫描器验证并注册；系统、项目、扩展包和插件的同名优先级由注册表统一决定。Pi 通过官方 `skillsOverride` 使用每轮冻结的注册目录，不再依据宿主状态目录二次发现技能，也不在执行前重新读取正文。激活技能保存选中版本的正文，目录与正文使用同一份回合快照；新增、修改和删除在后续租约刷新。项目指令缓存由各 Pi 会话独立持有，其他会话刷新不会改变当前租约的指令。无效项目技能保留源位置诊断、不进入可激活目录；设置与执行复用同一注册策略，避免一个损坏技能使普通对话或 MCP 配置校验整体失败。

宿主在启动时固定应用资源目录，所有工作区的运行时缓存和执行环境使用同一资源来源。内置扩展、提示词和技能来自应用资源目录，不随工作区目录改变；扩展配置继续严格校验。工作区用户插件从当前工作区 `.senera/user-plugins` 加载，项目插件从当前工作区 `.senera/plugins` 和项目 `plugins` 目录加载；两者由路径解析器明确区分，同一物理目录只扫描一次。旧版本应用级共享插件目录只作为有版本标记的迁移源，迁移到工作区用户插件目录后不再作为运行时扫描源，也不会静默改归属。

## 切换

侧栏顶部提供最近工作区选择和打开文件夹入口。桌面端使用系统目录选择器；浏览器使用服务器目录浏览器。设置页保留路径信息，不再承担切换流程。

浏览器目录选择器只保留路径栏、上一级操作、文件夹列表和打开按钮；路径提交与文件夹导航都可重复执行，旧请求在新导航时取消。打开按钮只使用已经加载的目录，切换成功后关闭窗口，失败时保留目录和错误信息。

打开工作区不重启共享 HTTP 服务。工作区目录在应用状态根目录的 `.senera/workspaces.json` 中登记稳定 UUID；最近打开的目录排在前面。`workspace.switch` 通过 `requestId` 返回结果，先发送切换确认，再停止没有其它客户端连接的旧运行时；如果切换时还有其它客户端，运行时会保留，等这些客户端全部断开后再回收。普通客户端断开不会误停仍可能承载后台任务的工作区。停止使用配置驱动的会话结算和资源清理，不额外引入固定超时。断线后可以使用同一请求恢复打开操作。

工作区列表通过认证的 `GET /api/workspaces` 读取。`DELETE /api/workspaces?workspaceId=<id>` 只移除应用目录中的登记，不删除目标目录、`.senera` 状态或项目文件；默认工作区和仍有客户端连接的工作区会返回冲突，必须先切换或断开连接。忘记后再次选择同一目录会生成新的登记身份，但目录内容保持不变。

同一 HTTP / WebSocket 监听端口按 `workspaceId` 分发请求。传输地址和 CLI 运行清单来自宿主的实际监听配置，配置热更新不会让新工作区连接尚未监听的新端口。前端切换连接时清除旧队列，并按连接来源隔离事件投影；刷新后的地址保留工作区 ID，宿主按需恢复对应实例。CLI 运行清单也携带工作区 ID，避免命令落到默认工作区。

失效的工作区 ID 是永久连接错误：通过认证的 WebSocket 使用 `4404 / workspace_not_found` 关闭，HTTP 返回 `404`，不会伪装成临时容量故障。浏览器停止自动重连，并通过宿主级 `GET /api/workspaces` 读取当前目录登记，让用户明确选择新连接；不会把旧 ID 映射到其他目录，也不会静默切换到默认工作区。恢复目录列表同样要求认证和来源校验，不需要启动任何工作区实例。

全局 localStorage 只保存界面及审批偏好。会话选择、模型、推理等级和用量使用独立的工作区存储键；消息正文由服务器权威回放，不在浏览器持久化。输入草稿按工作区和会话持久化；待上传附件在浏览器运行期间按同样的归属保持上传，File 和 Blob 不伪装成可刷新恢复的对象。切换时释放非当前工作区的浏览器消息投影，再按需回放。文件编辑使用 ETag 检查并发版本；外部修改保留当前草稿并提示重新加载。切换前有未保存文件时需明确选择保存或放弃。

## 文件

输入框 `+ → 工作区文件` 和文件预览共用 `@pierre/trees` 的紧凑目录树、虚拟化与完整文件图标。目录按展开加载，外部更新按路径增删，保留已展开目录和选择。搜索复用发布包中的 ripgrep，遵守根目录和嵌套 `.gitignore`，使用 fuzzysort 排序；搜索覆盖尚未展开的目录，只读取路径，打开预览时才检查文件内容。原生 `@parcel/watcher` 只在文件面板订阅期间启动，每个工作区共享一个监听；服务端发送 SSE，更新文件树与干净的文件预览。

文件默认只读，源码预览和显式编辑使用 `@pierre/diffs` 原生界面；Markdown 复用主对话的渲染器、阅读字号、行高和代码块，合法 JSON 对象和数组可以切换结构视图。视图选择位于右上角，与编辑图标共用工具栏，不占用内容区额外行。编辑器独立持有当前文档，修改通知只用于保存草稿，不反向覆盖编辑器。保存成功返回预览，ETag 冲突保留草稿并明确报错。工具栏只显示文件名和固定尺寸图标，操作说明悬停显示；文件树可收起，窄屏可切换到文件树。

源码先在官方 Worker 池中准备高亮，再挂载虚拟文件视口；加载期间显示现有加载状态，高亮失败明确报错并支持重试。Worker 使用 ES 模块，语言与主题按需加载，池与 AST 缓存各保留两项。文件路径和 ETag 组成缓存键，切换文件会取消旧读取请求，虚拟行定位不依赖不可见行的 DOM。JSON 只在选择结构视图时由单独 Worker 解析，源码展示不再触发 JSON.parse。Markdown、JSON、目录列表、源码视口和 Shadow DOM 内横向滚动共用项目滚动条样式及主题变量。

引用文件复用现有资源上传与附件协议，上传、预览、编辑及下载 URL 都携带同一工作区 ID。

高亮池只在预览挂载后创建，避免文件树资源暂挂导致重复启动；同一预览内切换文件复用池，关闭时统一释放。初始化失败保持错误状态，用户重试时重新创建池，不自动退回无高亮正文。

HTTP 宿主先用 `workspaceId` 解析资源所属工作区，再消费这个传输参数；业务路由只接收自身参数。上传及资源读取继续严格拒绝无关查询参数，资源不会跨工作区读取。打开文件时关闭输入框整个工具菜单，避免菜单残留在预览后方。

## 部署

- dev / 本地服务：可打开当前进程能够访问的目录，每个目录使用自己的 `.senera` 配置源和运行时状态。
- Electron：应用数据根目录只保存目录登记，最近选中的工作区另行持久化；配置、会话和 Electron userData 位于当前工作区的 `.senera`。安装程序只安装应用，首次启动选择项目；不在安装阶段配置工作区或移动旧目录。托盘入口复用主界面的目录选择流程。
- 容器镜像：默认允许启动目录及其子目录。可以通过 `SENERA_WORKSPACE_ROOTS` 配置 JSON 数组形式的额外服务器目录；这些目录必须已挂载到容器。使用共享沙箱 Worker 时，工作区也必须位于该 Worker 的挂载根目录之内，未挂载的目录会明确报错。

比如，容器以 `/data` 启动，可以在同一卷内使用 `/data/projects/app-a` 和 `/data/projects/app-b`。Compose 把应用状态单独挂载到 `/var/lib/senera`，项目和宿主使用不同的持久卷。浏览器不会把本机文件夹路径当作服务器目录。

工作区的持久化服务保存后台任务及定时任务状态；切换回收旧运行时会停止其当前调度、Pi、MCP、观察器和执行资源，重新打开时从持久化数据恢复。WebSocket 连接决定运行时是否仍被使用；仍有连接的工作区不会被另一个客户端切换动作误停，最后一个连接断开后才回收空闲实例。文件监听跟随面板订阅释放，宿主在全部工作区完成关闭后才关闭共享服务。

“数据与存储”设置通过认证的 `GET /api/application-storage` 默认显示应用状态和工作区 `.senera` 运行数据，不把源码、文档或其他项目文件误计入运行数据。需要完整项目文件占用时，前端显式请求 `scope=project`，服务端只在这次请求中扫描工作区根目录，并从项目统计中排除 `.senera` 状态目录。迁移备份通过 `GET /api/application-storage/migrations` 审计，清理必须提交工作区登记 ID 和备份 ID 的受保护 `DELETE` 请求；服务端会校验路径边界并原子更新迁移清单。内部容量、并发、开发端口和维护策略在配置表单源头标为 internal，不再作为普通用户的几十项设置投递。目录登记和桌面项目选择复用公共原子写入方法。
